# 鸣潮卡池抓取约束

更新时间：2026-09-13

## 1. 适用范围

本文档约束鸣潮（`ww`）当前角色、武器卡池的抓取、角色名称清理、图片来源和数据发布。卡池名称和时间以库街区官方接口返回值为准；角色活动页签必须先通过完整性和主推海报校验，才能写入当前卡池 JSON。

## 2. 官方来源与代码位置

- 库街区入口：`https://wiki.kurobbs.com/mc/home?bbs_clientSource=12`
- 当前卡池接口：`https://api.kurobbs.com/wiki/core/homepage/getPage`
- 角色详情接口：`https://api.kurobbs.com/wiki/core/catalogue/item/getEntryDetail`
- 当前卡池爬虫：`spider/spider/spiders/ww.py`
- 当前数据指针：`spider/data/meta.json` 的 `ww` 键
- 当前数据文件：`spider/data/ww/<开始时间>_<结束时间>.json`

请求必须携带 `wiki_type=9`、`source=h5` 和库街区入口作为 `referer`；详情接口使用 `id=<entryId>` 查询角色或武器名称及立绘。

## 3. 页签与条目过滤规则

### 3.1 模块类型

- 仅处理 `角色活动唤取` 和 `武器活动唤取` 两个官方模块。
- `角色活动唤取` 的输出类型为 `角色`；`武器活动唤取` 的输出类型为 `武器`。
- 页签时间必须存在开始和结束时间，并规范化为 `YYYY-MM-DD HH:MM:SS`。

### 3.2 条目完整性

每个图片条目必须同时满足：

1. `linkConfig.entryId` 非空；
2. 详情接口返回非空角色/武器名称；
3. 卡片图片地址非空。

任一条目不满足条件，丢弃整个页签，不得只保留首项。这样可以避免官方接口返回残缺图片时，把四星角色或错误图片提升为独立限定卡池。

角色名称写入前必须执行首尾空白清理；图片地址也必须清理首尾空白。

### 3.3 角色限定池判据

角色页签必须至少有一个非空 `largeImg`（角色详情中的“海报立绘”）才能发布。没有主推海报的页签视为四星/残缺/非限定页签，直接丢弃。

该规则只决定“页签是否作为当前角色卡池发布”，不表示四星陪跑角色不存在。已发布的有效角色页签仍可保留官方返回的陪跑角色列表。

## 4. 图片来源与命名

- 小图优先取角色详情“基础信息”图；缺失时回退到官方卡池图片地址。
- 大图只取角色详情“海报立绘”，不得使用小图或卡池横幅冒充。
- 本地图片保存到 `spider/img/ww/`，命名为 `<角色或武器名称>.png`。
- `img_path` 必须与清理后的名称一致，禁止生成带前导/尾随空格的文件名。

## 5. 前端兼容约束

前端读取鸣潮旧 JSON 时仍需执行兼容过滤：

- `gachas` 非空；
- 每个条目都有非空名称和图片；
- 至少一个条目有非空 `largeImg`。

过滤后再展开卡片；鸣潮当前首页只展示有效页签的首项主推角色，不得在过滤前使用 `gachas.slice(0, 1)` 把残缺页签首项渲染为“限定”卡片。卡池“限定”徽标属于有效角色页签，不代表其中每个陪跑角色都是限定角色。

## 7. 发布前检查

1. 运行 `python -m unittest discover -s tests -v`。
2. 运行 `python -m compileall -q spider`。
3. 校验当前鸣潮 JSON 的角色页签均通过完整性检查，且至少一个角色有 `largeImg`。
4. 校验 `img_path` 文件存在，名称无前导/尾随空格，旧错误文件不再存在。
5. 运行 Web 的 `npm run lint` 和 `npm run build`。
6. 发布后单独核对线上 `data/meta.json`、当前鸣潮 JSON 和页面渲染；本地构建通过不等于线上抓取和页面验收通过。
